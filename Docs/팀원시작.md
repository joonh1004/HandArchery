# 팀원 시작 안내

## 실행만 할 때
제작자가 전달하는 `Windows` 폴더 전체를 로컬 디스크에 복사합니다. exe, Data 폴더, MonoBleedingEdge, UnityPlayer.dll, ThirdParty 등을 함께 유지합니다. `HandArchery.exe`를 실행하면 됩니다. Unity나 Python 설치는 필요하지 않습니다.

실제 시연 노트북에서 첫 실행을 미리 해보세요. 카메라가 목록에 잡히는 것과 양손 추적이 되는 것은 별개입니다. 다른 카메라 사용 앱을 닫고 게임의 **입력 재시작**을 눌러 봅니다. 보안 설정을 자동 변경하거나 권한을 우회하지 않습니다.

## 개발할 때
아래 명령은 `HandArchery` 루트 폴더에서 PowerShell을 열고 실행합니다.

1. Unity Hub와 Editor **6000.6.7f1**, Windows 빌드 모듈을 설치합니다.
2. 저장소를 로컬 폴더로 받습니다. 현재 로컬 구현은 아직 원격에 반영하지 않았으므로 최신 소스가 전달됐는지 먼저 확인합니다.
3. Git LFS를 설치하고 프로젝트에서 `git lfs install`, `git lfs pull`을 실행합니다. 폰트·모델에 실제 내용이 있는지 확인합니다.
4. PowerShell에서 `./Tools/PrepareMediaPipe.ps1`을 실행합니다. 공식 패키지 약 290MB를 받고 고정 해시를 검사합니다.
5. Unity Hub의 **Add project from disk**로 루트 폴더를 등록합니다. 첫 import는 시간이 걸릴 수 있습니다.
6. `Assets/HandArchery/Scenes/HandArchery.unity`를 열고 Play를 누릅니다. 게임은 기본적으로 실제 카메라를 사용합니다.

PowerShell이 스크립트 실행을 제한하면 시스템 정책을 임의로 완화하지 말고 담당자와 확인합니다. 빌드는 Unity 메뉴에서도 가능합니다.

## 수정 역할 나누기
입력 담당은 `Input`, 규칙 담당은 `Core`, 게임 담당은 `Runtime/Gameplay`, 화면 담당은 `Runtime/Presentation`을 중심으로 작업합니다. 공용 타입과 설정을 바꿀 때는 다른 담당자와 먼저 맞춥니다. 씬은 SceneFactory가 구성하므로 수동 변경을 자동 재생성으로 덮지 않도록 보존합니다.

작업 파일과 `.meta`를 함께 공유합니다. `Library`, `Temp`, `Logs`, `Builds`, `Packages/Local`, 영상·로그인 정보·API 키는 올리지 않습니다. 패키지·모델·폰트의 라이선스 고지를 유지합니다.

## 빌드와 검사
Unity 메뉴 **HandArchery → Build Windows Archery** 또는 Editor를 닫고 `./Tools/BuildWindows.ps1`로 빌드합니다. 출력은 `Builds/Windows`입니다.

`./Tools/RunArchery.ps1`은 실제 카메라 모드입니다. `./Tools/RunArchery.ps1 -SyntheticCheck`는 별도 자동 검사입니다. 검사 창을 활성화하고 완료를 기다립니다. 화면에 **실제 손 검증 아님**이 표시됩니다.
